# M&E ↔ M'Cheyne Pairing — Review Report

Generated by `analysis/build_schedule.mjs`. Deterministic; re-running from a
clean `out/` reproduces this byte for byte.

**A devotional is paired to a day only when its own scripture falls inside what
the plan reads that day.** The day that reads Genesis 1 gets a devotional built
on Genesis 1:4. Nothing else places anything:

- the devotional's position in Spurgeon's original calendar is ignored entirely
- no AM/PM semantics
- **no fillers** — a day with no scripture match stays open and empty

Each day therefore holds 0, 1 or 2 devotionals, and every pairing in the
schedule is a real one. Days are left open rather than padded.

## Same-chapter and same-verse pairings

Two devotionals on the identical verse add no coverage of the day's reading —
they say the same thing twice. That is a **hard exclusion**. Two on different
verses of one chapter are legitimate, just narrower than two chapters, so
same-chapter remains a scoring preference only.

## Overrides

`analysis/out/schedule-overrides.json` is read at the start of every run and
applied after matching, so hand corrections survive a re-run. Created as `{}` if
absent. Keys are `MM-DD`; values name 0, 1 or 2 devotional keys:

```json
{
  "08-07": {
    "devotionals": ["03-12-AM"],
    "note": "why this override exists"
  }
}
```

An override replaces that day outright and releases whatever was there. An empty
`devotionals` array forces a day open. Overrides bypass the scripture-match
assertion, so a hand-placed devotional need not match the day's readings.
